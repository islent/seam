# 派生：给定一个参数，怎么定下它的控件

> 拿到一个陌生程序，输出一份清单。每一步的答案都要来自代码，不来自名字，也不来自文档的口气。

## 三步

```
① 能不能改？ ──→ 只能读 ──→ 读数
      │
      └─ 能改 ──→ ② 能填什么？ ──→ 没有值 ──→ 按钮
                       │             几个选项 ──→ 下拉
                       │             一段范围 ──→ ③
                       │             说不清 ──→ unresolved
                       └─→ ③ 什么时候能改？ ──→ 决定滑杆灰不灰
```

## 第一步：能不能改

问题：这个值，程序会读回去吗？

按可靠性从高到低：

1. **真跑一次**：写进去，看下一次采样变没变。
2. **看代码**：找到读它的那一行。`self.resolution` 在构造函数里被用来建网格 → 能写，但只写一次。
3. **看函数签名**：`def __init__(self, resolution=20, ...)` → 它是输入。
4. **看文档**：作旁证。
5. **看名字**：不作证据。

读不回来的是**读数**，到此为止。

## 第二步：能填什么

| 代码里看到的 | 结论 | 例子 |
| :--- | :--- | :--- |
| 无参数的方法 / 动词式子命令 | 按钮 | `sim.reset()`、`--stop` |
| `bool` / `type=bool` / `0/1` 标签 | 下拉（两个选项） | `eps_averaging` |
| `choices=` / `Literal[...]` / 一个 `switch` | 下拉 | `open` / `periodic` / `pml` |
| `int` 但合理取值只有几个 | 下拉 | `dimensions ∈ {1,2,3}` |
| `float` 加上下界（代码里有范围检查） | 滑杆 | `until ∈ [5, 2000]` |
| `float` 没有任何范围 | unresolved | 无界的系数 |
| `dict` / `list` / 路径 | 拆开每个字段各算一个参数 | 一整个配置块 |

## 第三步：什么时候能改

| 观察到的事实 | 结论 |
| :--- | :--- |
| 构造函数 / 解析配置 / 启动时读一次 | `sealed` |
| 每步（或每个时间步）从通道读一次 | `perstep` |
| 任何时候读，甚至有线程在监听 | `midrun` |
| 不知道，但架构上像读一次 | 按 `sealed` 处理，备注「未验证」 |

**没有真跑过的 `midrun` 是不合规的。** 一个能拖但没用的滑杆和一个能拖并且有用的滑杆，
在屏幕上完全一样；允许「我觉得它能改」，整份清单的可信度就归零。

不确定时：标成 `sealed`，备注「未验证，需一次探针运行」。

## 探针：不同程序怎么试

### Python 对象

```python
import inspect
print(list(inspect.signature(mp.Simulation.__init__).parameters))   # 启动参数

sim.run(until=100)
sim.resolution = sim.resolution * 2   # 赋值不报错
sim.run(until=200)
# 值变了不等于参数生效 —— 看网格有没有重建，或看 step 计数怎么走
```

### 命令行工具

```python
for a in build_parser()._actions:
    print(a.dest, a.type, a.default, a.choices)
```

拿不到 parser 的，读 `--help`，但那是 E2。

### 文本配置文件（`begin:... end:...`）

```bash
grep -E '^\s*(begin|end):' input.deck
```

块里是 `键 = 值`，值常见 `400 * femto` 这种带单位的表达式；按原样保留字符串，或写一个最小求值器。

这类程序通常在启动时把整个配置读完，之后再也不看 —— 所以绝大多数是 `sealed`，由架构决定。

### `标签 值` 参数文件

```
TimeMax                  0.25
TimeBetSnapshot           0.05
```

**不要写 `=`。** 读它的代码是 `sscanf("%s%s%s")`，`TimeMax = 0.25` 会把 `=` 当成值读进去，
之后每一行都错位。

**单位要和程序对齐。** Gadget-2 的 `TimeMax` 用它自己的时间单位（1 单位 ≈ 0.9778 Gyr）。
清单里写明换算，界面显示 `0.244 Gyr`，提交 `0.25`。

### Julia 结构体

`@kwdef struct` 的字段：类型、默认值都在，是 E1。不可变结构体在语言层面禁止中途改字段，
所以基本都是 `sealed`，除非程序提供了每步回调 —— 那就是一个现成的 `perstep` 通道。

## 判不出来的时候

```toml
[[param]]
name = "convergence_tol"
affordance = "unresolved"
reason = "代码里找不到读它的地方，也不在构造函数里；文档说可以调，但没有证据"
```

界面上显示成一行带说明的文字。从一份真实的 EPOCH 配置派生时，14 个参数里有 11 个是这种情况：
光看配置文件，不知道能不能改。

## 速查表

| 能不能改 | 能填什么 | 什么时候能改 | 控件 |
| :--- | :--- | :--- | :--- |
| 不能 | — | — | 读数 |
| 能 | 没有值 | 任意 | 按钮 |
| 能 | 两个 / 几个选项 | 任意 | 下拉 |
| 能 | 一段范围 | 启动前定死 | 滑杆（灰掉） |
| 能 | 一段范围 | 两步之间 | 滑杆（排队生效） |
| 能 | 一段范围 | 随时 | 滑杆（立即生效） |
| 能 | 没范围 / 结构化 | 任意 | unresolved |
| 不知道 | 不知道 | 不知道 | unresolved |

第四、五、六行的控件完全一样，行为完全不同 —— 这就是 `liveness` 必须显示在控件上的原因。
